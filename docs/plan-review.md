首版优先鸿蒙原生运行，在 PC 本机完成真实开发。
同机 Linux 融合开发引擎暂不纳入方案。

## A 首版交付什么

```callout info PC 本机完整开发
在同一台鸿蒙 PC 上运行 daemon、代理 CLI、Git 和终端。
完成修改文件、执行测试、查看输出和审阅 diff。
```

平板和手机连接这台 PC，跟进任务并回应权限请求。
本机执行环境通过验证后，才进入完整产品开发。

## B 哪些组件需要协作

```flow
鸿蒙应用 -> Web业务层: 复用界面
Web业务层 -> 本机daemon: 认证连接
本机daemon -> 代理CLI: 执行任务
本机daemon -> Git和终端: 开发工具
代理CLI -> PC工作区: 修改文件
Git和终端 -> PC工作区: 测试与审阅
平板手机 --> 本机daemon: 跨设备连接
group 同一台鸿蒙PC: 鸿蒙应用, Web业务层, 本机daemon, 代理CLI, Git和终端, PC工作区
```

daemon、代理、Git 和 PTY 均以鸿蒙原生运行为目标。
P0 先验证运行时、签名、进程及原生依赖。

## C 先验证哪条本机路线

| 路线 | 优势 | 尚需验证 | 建议 |
|---|---|---|---|
| 直接运行于鸿蒙 | 符合用户选择 | Node、HNP、签名、PTY、代理 | 当前主线 |
| 同机融合开发引擎 | 已有资料可参考 | 用户当前不接受 | 暂不采用 |
| 另一台机器运行 | 可用于排查界面 | 不符合本机目标 | 仅作对照 |

原生执行链尚未通过应用级验证。
优先评估 Harmony Electron，另比较 ArkWeb 宿主。

## D 分阶段如何交付

以下为单人工作日预算，尚未开始实施。

| 阶段 | 预算 | 交付 |
|---|---|---|
| P0 可行性验证 | 4–6 日初始调查 | 原生执行缺口、签名和宿主选择 |
| P1 本机任务 | 3–5 日 | HAP 与一次真实代理任务 |
| P2 任务可靠性 | 5–8 日 | 会话、权限、连接恢复 |
| P3 PC 开发体验 | 5–8 日 | 终端、编辑器、diff、键鼠 |
| P4 PC 系统集成 | 4–6 日 | 文件授权、生命周期、诊断 |
| P5 平板与手机 | 4–6 日 | 布局、触控、跨端恢复 |

原先 6–9 周总预算不再适用于当前原生主线。
原生基础可用后，P1–P6 功能预算为 24–38 日。
底层移植与审批工期由 P0 实测后重估。

## E P0 必须拿到哪些证据

| 门槛 | 必须证明 |
|---|---|
| 真机连接 | hdc 可识别，并可安装签名 HAP |
| 执行环境 | 该 PC 上的 Node、PTY、Git 和真实代理可用 |
| 本机完整链 | 修改文件、运行测试、查看 diff |
| 前端宿主 | 中文 IME、xterm、CodeMirror、存储和连接可用 |
| 发布条件 | 可重复打包；签名与权限满足选定路线 |

原生路线遇阻时，提交证据和原生解决方案。
不能自动切换为远程或 Linux 子系统执行。

## F PC 首版怎样验收

- 中文组合输入不会误发任务。
- 权限请求能批准和拒绝，并避免重复执行。
- 终端支持真实 PTY、Ctrl+C、缩放和中文。
- 保存内容与本地 Git diff 一致。
- 断线后补齐消息，恢复任务和工作区。
- 本机测试服务有可用预览入口。
- 连续两小时操作，无崩溃或冻结。

首版先验证一个真实 provider。
语音、推送、多窗口和浏览器自动化随后增加。
